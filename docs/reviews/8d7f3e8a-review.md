## Spec

### F1：[P1] 进程异常退出遗留索引锁，导致后续新建会话持续失败

**位置：**`src/session-index.ts:33–40`。\
**需求关联：**Spec 的高可靠目标及 Session Persistence & Cross-Client Resumption。

#### 问题与影响

索引写入通过 `mkdir(lock)` 获得跨进程目录锁，正常退出在 `finally` 中删除。进程获得锁后被强杀或主机异常退出时，清理不执行，锁目录永久遗留。后续进程只会等待五秒并失败，重启 IDE 或桥接器不能修复；需要人工删除锁目录。由于新建会话需要写入索引，该故障会持续阻止新会话创建。

#### 复现路径

1. 在临时索引路径旁制造一个代表已退出写入进程的遗留锁目录。
2. 使用新的 `SessionIndex` 实例调用 `set()`。
3. 当前实现等待约五秒后失败；再次尝试仍失败。

本轮结论来自代码路径检查，未实际强杀用户进程。现有 `test/session-index.test.ts` 只覆盖正常并发写和损坏索引，不覆盖遗留锁。

#### 修复方向

选择具备崩溃释放语义的锁，或采用包含所有者信息且能够安全恢复的陈旧锁机制。不能简单地超时强删锁：活跃但较慢的写入者也可能超过阈值。恢复过程本身也必须避免两个新写入者同时获得写权限。

#### 验收标准

- [ ] 遗留锁存在时，新进程可安全恢复索引写入，不依赖用户人工清理。
- [ ] 活跃进程持有的锁不会仅因超时被抢占。
- [ ] 两个并发写入者不会丢失任何会话映射。
- [ ] 损坏的索引仍被明确拒绝，不被空索引覆盖。
- [ ] 正常及异常路径不遗留本次测试的锁、临时文件或子进程。

### F2：[P2] 模型切换期间关闭会话，会在 dispose 后继续修改会话

**位置：**`src/server.ts:75–88、192–198`。\
**需求关联：**Spec 的会话关闭与资源清理要求。

#### 问题与影响

`changingModel` 阻止提示和重复切换，但 `dispose()` 只等待 `entry.active`，不等待异步 `setModel()`。可能出现以下顺序：

1. `session/set_config_option` 开始模型切换，等待认证检查。
2. 客户端发送 `session/close`，会话被 dispose，关闭成功返回。
3. 认证检查完成，旧的 `setModel()` 继续修改状态、追加模型历史，并返回切换成功。

本地 Pi SDK 的 `setModel()` 确实先 `await checkAuth()`，再修改模型状态、追加模型历史和发出模型选择事件，因此不是单纯的布尔标记问题。

#### 已有复现证据

本轮使用内存 ACP 协议测试并注入可暂停的 `setModel()`：等待切换进入后发送 close，观察到 dispose 已完成；随后释放切换，观察到切换继续执行并返回成功。临时测试已清理，不在仓库中；修复时应添加正式回归用例。

#### 修复方向

跟踪模型切换操作的结算 Promise。关闭开始后禁止新操作；等待正在执行的操作完成或可靠取消后，再执行扩展 shutdown 和 dispose。不要只添加另一个布尔判断，也不要让关闭因遗漏结算而永久等待。

#### 验收标准

- [ ] 延迟认证/模型切换与 close 交错时，dispose 后不再发生模型状态或历史修改。
- [ ] 同样的规则适用于连接断开和服务器 shutdown。
- [ ] 切换失败仍能释放 busy 状态，关闭能正常完成。
- [ ] 关闭开始后，同一会话不再接受新的提示或模型切换。
- [ ] 现有提示取消、重载中关闭和扩展清理行为不退化。

### F3：[P2] 当前模型不可用时，其他可用模型的选择入口也被隐藏

**位置：**`src/models.ts:6–9`。\
**需求关联：**Spec 用户故事 2：通过 IDE 模型下拉框切换模型，无需重复配置。

#### 问题与影响

`modelConfigOptions()` 在当前模型不属于可用快照时直接返回空数组。恢复旧会话时，旧模型可能已删除、下线或失去认证，但用户仍有其他可用模型。此时整个模型选择入口消失，用户无法从 IDE 切换到可用模型继续会话。

文档目前建议补齐旧模型认证后重连，但这无法解决旧模型永久下线、用户只想改用其他模型的正常场景。这是已文档化的产品限制，仍构成相对需求的恢复能力缺口。

#### 复现路径

提供一个当前模型为 A 的会话，其可用模型快照只包含已认证的 B，调用 `modelConfigOptions()`，当前返回 `[]`。应在协议层覆盖恢复会话及随后选择 B 的行为。

#### 修复方向

只要存在可用模型，就应保留可恢复的选择路径。先核对 ACP select 配置对 `currentValue` 的要求，再确定采用明确替代模型还是其他协议允许的策略。不得把未认证模型伪装成可用项，也不得未经说明改写全局默认模型。

#### 验收标准

- [ ] 恢复会话当前模型不可用、但另有可用模型时，用户可在 IDE 选择可用模型并继续会话。
- [ ] `currentValue` 和选项符合 ACP 配置契约，不向 UI 报告与实际模型不一致的状态。
- [ ] 切换不修改其他会话或全局默认模型。
- [ ] 没有任何可用模型时，明确反馈不可用状态，不伪造选项。
- [ ] 文档同步说明恢复策略，删除或修正过时的限制描述。
